# Проект по созданию и сравнению моделей для автодополнения текстов на основе LSTM и трансформеров.

## Цели проекта:

    1. Реализовать легковесную модель на основе LSTM.
    2. Протестировать предобученную модель трансформера (DistilGPT-2).
    3. Сравнить производительность и качество обеих моделей.
    4. Дать рекомендации по использованию в условиях ограниченных ресурсов.

## Установка
### 1. Клонирование репозитория
git clone https://github.com/Computer-vision-science/text-autocomplete.git
cd text-autocomplete

### 2. Создание виртуального окружения
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
или

pip install -r requirements.txt

## История-дневник проекта:
Получился проект проб и ошибок, но с простым решением. Взята большая база 114 МБ твитов на английском языке. Сначала определялся формат примеров. 

1) Взяты примеры по принципу скользящего окна. То есть X = токен № 1, Y = токен № 2, X = токен № 1 + токен № 2, Y = токен № 3, X = токен № 1 + токен № 2 + токен № 3, Y = токен № 4 и так далее. Проведен паддинг до 128 нулями. Тренировочный датасет стал размером более 9 гигабайт. Обучение даже на Colab = 3 часа на эпоху. На ПК с видеокартой NVIDIA GeForce RTX Laptop GPU на 6 Гигабайт с оперативной ппамятью ПК 32 Гигабайта DDR4 процесс совсем не запускался.

Подход признан неудачным исходя из имеющихся ресурсов.

2) Взяты примеры по принципу из пункта № 2, но паддинг проведен до 64, потеряны данные всего из 11 строк. И размер тренировочного датасета существенно снизился - до 5 Гигабайт. Валидационный и тестовый датасеты составили до 1 Гигабайта.
Обучение одной эпохи на видеокарте ПК 66 часов. Вариант мог быть признан неудачным...
Проведена широкая оптимизация кода. Принято решение дополнительно сконвертировать файлы формата .csv в формат .npz, чтобы не ждать формирование датасетов в случае изменения опций DataLoader.

## ПРИНЦИПЫ ПРОЕКТА

1. Код является авторским и может использоваться без каких-либо ограничений.
2. Действует принцип одного окна. Все процессы проходят в файле solution.ipynb. Импорты встраиваются в общий процесс отдельным скриптом, поэтому запуски файлов из папки src НЕВОЗМОЖНЫ!
3. Можно использовать совершенно любые датасеты, загрузив их в папку data, отметив особенности в функции clean_string файла data_utils.py.
4. Данный проект можно назвать коробочным решением, работающим как есть.
